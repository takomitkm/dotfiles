# ⛔ 已证伪 — 不要运行

## `patch-runner-node.py` 是什么

它试图把 DSH 的私有 subprocess runner 从 Electron 换成随包 `node.exe`，以省内存。

## 为什么不能用（2026-11-03 实测，方案作废）

`runner.js` 及其依赖都在 **`app.asar` 内部**，而**只有 Electron 的 node 能读 asar**（Electron 给 `fs` / 模块加载器打了 asar 补丁）。用官方 `node.exe` 启动会直接失败：

```
Error: Cannot find module
  'C:\…\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-subprocess-local\lib\runner.js'
    at Module._resolveFilename
```

宿主侧表现为：

```
subprocess-local: Windows Job runner exited with exit code 1
  before proving its managed range empty
```

**所有子进程类工具全挂**（实测 `pwsh` 工具直接失败）。所以 `process.execPath` 是"唯一能读到自己 asar 内 runner 的运行时"，不是疏忽。

完整记录见：`S:\apps\llm\agentwork\LOCAL-DIVERGENCE.md` 的「A1/A2 + 为什么不能用 node.exe 当 runner」。

## 真要走这条路只有三条

1. 把 runner 及依赖 unpack 到 `app.asar.unpacked` 再用 node.exe（依赖链长，工程量最大）。
2. 接受 Electron runner。
3. 绕开一次性 spawn，改用持久 PTY —— **已采纳**，就是 `dsh-tool-pwsh-persistent`（见桌面 `dsh初始化.py`）。

## 本目录保留它只是存档

工具本身（status/apply/rollback）逻辑完好，但**结论是不用**。任何时候都**不要**对生产 asar 跑 `apply`。
