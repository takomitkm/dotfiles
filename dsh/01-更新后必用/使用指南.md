# 更新后必用脚本 —— 快速指南

## 🎯 何时使用

App 自动更新（版本号变化、app.asar mtime 变为今天）之后 **第一时间运行** `dsh-fix.py`，否则两类已知崩溃会复发：

| Bug | 触发条件 | 表现 | 状态 |
|---|---|---|---|
| #9271 inspector | Cordis 树 ≥ 8 MiB | Host exit 1, fatal uncaught exception | ✅ P1 已打 |
| #9575 storage-json | Windows 瞬时文件锁 | EPERM rename → fatal load failure | ✅ P2 已打 |

## 📌 核心命令

```powershell
# 查看当前补丁状态（推荐先用这个确认）
python "dsh-fix.py"

# 打印状态详情
python "dsh-fix.py" status

# 打补丁（DSH 运行中可强制 --yes，实际生效需重启）
python "dsh-fix.py" apply --yes

# 回滚到最新备份（撤销最近一次 apply）
python "dsh-fix.py" rollback --yes
```

### 输出示例

```text
P1 inspector (#9271):
  index.js   ✓ 已打
  client.js  ✓ 已打

P2 storage-json (#9575):
  index.js   ✓ 已打
```

如果显示 ✗ 未打，说明 App 更新了 or rollback 过；立刻 run `apply --yes`。

## ⛔ Runner 补丁：已证伪，不要用

`patch-runner-node.py`（换 node.exe 当 runner）**2026-11-03 实测证伪**：`runner.js` 在 `app.asar` 内，只有 Electron 的 node 能读 asar，官方 node.exe 会 `Cannot find module` → 所有子进程工具全挂。已从本目录移出到 `06-已证伪勿用\`，**不要 apply**。

绕开一次性 spawn 的正确做法是持久 PTY（`dsh-tool-pwsh-persistent`，见桌面 `dsh初始化.py`），与实际结论一致。

## 🧩 更新后重打（一条命令）

按 2026-11-07 的约定不提供 .cmd 包装层，直接跑：

```powershell
python "dsh-fix.py" apply --yes
```

## ⚠️ 重要提醒

1. **App 升级 = 补丁丢失**：每次 DSH 自动更新必须重新 `apply --yes`。
2. **回滚安全**：`rollback --yes` 只恢复 asar，不影响 profile、存储数据、用户设置。
3. **双保险组合拳**：
   - inspector 已 `disabled: true` in cordis.patch.yml（额外防护）。
   - storage-json retry 是临时兜底，等官方 upstream 合并后可移除。
